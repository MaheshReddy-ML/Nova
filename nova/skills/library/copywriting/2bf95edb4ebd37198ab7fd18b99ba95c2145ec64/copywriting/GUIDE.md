# Copywriting

One sentence: NOVA diagnoses the copy situation first, then writes or edits with a strict quality gate that protects the user's voice, prevents AI tells, and ensures every claim is supportable.

## When to use

- User asks to write or rewrite page copy (homepage, landing, pricing, feature).
- User asks which headline, promise, or message to lead with.
- User provides a draft that needs voice restoration or a point-edit request.

## Workflow (numbered steps adapted to NOVA's tools)

1. **Diagnose the situation.** Determine if input is A (blank/generic), B (real voice present), or C (point edit). State diagnosis in one line with evidence before writing.
2. **Gather context.** Ask for page purpose, audience, product/offer, and traffic context if not provided.
3. **Decompose and lock.** Break the page into named units (headline, subhead, CTA, sections). Draft two or three candidates per unit, keep the best, fix its worst flaw, then assemble and read for flow.
4. **Apply the three-question gate to every line.** Can the reader picture it? Can it be proven true or false? Could a competitor write this exact sentence? If any answer is no, sharpen or flag `[NEED: ...]`.
5. **Ration the punch.** Most lines should be plain and specific. Reserve one or two punchy moments (usually headline and one section). Remove stacked devices that read as AI.
6. **Run the leave-it-alone test.** Check each change: is it measurably better, or just different? Revert changes you cannot justify.
7. **Run the No AI Tells self-check.** Search for banned patterns, read every sentence over 20 words aloud, fix from facts, flag missing proof as `[NEED: ...]`.
8. **Output page copy, annotations, and headline/CTA alternatives** as specified in the skill.

## Quality bar (checklist)

- [ ] Diagnosis stated with evidence before first draft.
- [ ] Three-question gate applied to every line (picture, provable, swap test).
- [ ] No AI tells: no contrast reveals, negation lists, trailing pile-ons, self-answered questions with colons, stock openers, em dashes in short copy.
- [ ] Claims are supportable; declined claims name the exact evidence that would unlock them.
- [ ] User's voice preserved (vocabulary, sentence length, paragraph habits, word choices matched if a sample was provided).
- [ ] One idea per section; logical flow down the page.
- [ ] Specific over vague; benefits over features; customer language over company language.
- [ ] One or two punchy moments max; no stacked devices.
- [ ] Leave-it-alone test passed: every change is justified as measurably better.
- [ ] No AI tells self-check passed (banned patterns searched, sentences over 20 words read aloud).
- [ ] Output formatted: page copy organized by section, annotations for key elements, 2-3 headline/CTA alternatives with rationale, meta content if relevant.

## Pitfalls

- Imposing NOVA's taste on user's existing good choices (diagnosis prevents this).
- Inventing stats, customers, or results; all claims must be supportable or flagged `[NEED: ...]`.
- Adding sections, claims, or structure the user didn't ask for (scope choice).
- Using AI tell patterns: "It's not X, it's Y," negation lists, trailing pile-ons, stock openers, em dashes in headlines.
- Stacked rhetorical devices that read as AI-generated; ration the punch.
- Dropping a declined claim without naming the evidence that would unlock it.
- Ignoring the user's writing sample voice (sentence length, punctuation, vocabulary).
